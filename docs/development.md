# 开发与验收

研究收尾增加 closeout.py 的只读清单、新版本导出和文件核对，回归覆盖选择文件范围、源文件不变、目标越界、大小写冲突、旧交付编辑保护与外部引用不被获取。归档测试覆盖不同阶段和真实用户来源要求，普通导出不改变项目状态。材料取舍、科学判断、实际复现与告别语气仍以具体材料和对话验收，文件摘要检查不代替它们。

轻量分类输入由 intent_seed 限制字段和大小，validate_intent_result 校验模式、目标白名单、只读约束和请求关联，分类不会授权执行或新建 session。两个宿主定义由同一提示词和模型策略生成，安装包测试检查配置可解析与独立可用。真实 Luna 试用和合成单元测试分别记录，Claude 原生调度、节省额度的幅度及 session 建议质量需在实际宿主使用中观察。

路由层使用 routing.py：发现限制在明确项目边界，语义模式由 Agent 选择，脚本约束字段、记录集合、字符预算和来源导航。阶段文档的发布、来源变化提示、封存与归档导航使用隔离回归测试；普通请求与查询保持只读。模式识别质量还需人工对话验收，脚本测试不代替语义评估。

Mid 八项与 Post 七项流程随当前入口发布，逐项提供输入、核验动作、记录、完成依据和回传。回归检查覆盖全部模式、具体任务引用、显式目标优先、方案到运行再到分析的有限依赖，以及稿件只接入关联主张；同一数据设置不扩大到其他实验。`evidence.py` 核对真实批准来源、冻结范围、设置版本、有限 run_keys 和尝试预算，接续已有任务并保留失败尝试，结构结果不代替实际执行前核验。

`preparation.py` 维护准备总表、冻结设置、Todo 与变更影响，普通 status/changelog 保持只读，report 才显式重建可读投影。回归检查覆盖定义保护、新版本对旧结果的追溯、待办重新待审、中断恢复和独立安装，以及领域摘要从锚点或画像更新时的同步。行为验收同时检查实际用户理解、设置核验质量与阶段取舍，不能仅依据结构检查判定科学准备完成。

使用 uv 管理依赖与执行，`uv sync --group dev --frozen` 建立环境。运行 `uv run pytest` 验证记录、状态、恢复、上下文定位与打包，`uv run ruff check .` 和 `uv run ruff format --check .` 核对代码。`uv run python scripts/build_skills.py --check` 检查安装资源同步，`uv run python scripts/build_skills.py --package` 生成可安装压缩包。

测试使用临时虚构项目和小型文本文件，不运行科研模型、真实数据评价、远程作业或外部服务。它验证文件与流程不变量，对话行为另通过案例人工审阅。采用 pytest 夹具模拟写入中断、人工修改和状态边，保留用户文字和来源记录。

首次对话的验收包括模糊兴趣、完整背景、多痛点、未知路径和用户修正；main 的验收包括目标数据被忽略、AI 建议被误当共识、恢复后重复工作以及范围外扩。候选名字、方向与机制采用真实讨论的原则，不用固定问答文本匹配代替语义评估。详见 [dialogue cases](../tests/dialogue-cases.md)。

Init 收束还需观察完整理解段落、推荐计划与排期、共同修订和 Main 接续；工作区检查核对所有档案落在 `.rondal/`。自动测试覆盖正文版本保存、工作区路径映射及已选计划的定位，生成式理解与排期质量仍通过实际对话评估。

Main 行为评估还包括广读后的核心对象选择、用户摘要与 AI 摘要分离、复现范围与源实现保真、主观状态的来源和时效、停滞后的具体行动，以及阶段证据与转移建议。阶段条件和理解质量需要观察实际对话与材料，不能用关键词匹配或打包检查宣称已验证。

前期与适配检查覆盖核心阅读后选基线、数据和评价协议、目标机器环境、资源观测时效与单设备显存、远程路径保留，以及视图编辑保护和批注回收。自动测试使用合成机器记录和隔离笔记目录，不连接真实 SSH、安装环境或修改 Obsidian 配置；文件级兼容与实际应用界面体验分别记录。示例见 [前期交互](../examples/preparation/README.md)和 [笔记视图](../examples/obsidian-notes/README.md)。

当前仓库可选执行本地记录命令，不包含自动科研运行。准备发布前核对 git 忽略项与构建清单，私人聊天映射与实际研究档案不进入安装包。独立行为试用可在研究者明确范围后开展，报告区分工程验证与对话评估。
