# 0.1.1：初始化入口与持久化修复

本次实际使用中，新项目已经开始相识与阅读讨论，工作区却没有生成档案。核对用户引用的对话发现，Windows 的 python 命令无法启动实际解释器，替换后又因缺少 yaml 模块使 discover 和 intent 失败；之后流程继续，但未调用记录初始化。旧版把首次落盘推迟到访谈收束，加上文档顺序先强调分类，导致失败没有及时阻断持久化声明。

规范目录统一为 `.rondel/`，旧 `.rondal/` 保留兼容发现。新增 routing.py enter，先在当前用户明确工作区检查档案，首次启动且允许保存时创建 listening 档案并实际读取验证，随后才开始渐进访谈。已有档案只读取项目、阶段与当前任务提示，生成短 intent_seed 后调用轻量分类，校验结果后才组装具体模式的 packet。

安装包内置 PyYAML 6.0.3 的纯 Python 模块和原许可证，直接运行辅助脚本无需依赖系统预装 PyYAML。使用有效解释器并在无 site packages 环境中测试，避免把开发机依赖齐备当成安装包可用。脚本失败时明确未保存并处理真实错误，重要访谈回答在最小档案中及时回写，最终理解、计划与 ready 仍按实际共同审阅形成。

迁移只对明确工作区内有效的旧档案原地更名，保留记录、来源、版本和历史。只读、双档案冲突、活动写入或未恢复事务时保留原状，返回具体处理位置，避免自动覆盖。已有文件与目录不会因找不到规范名字而被另一套空档案替代。

新增十项回归覆盖首次落盘、只读与缺来源不写入、已有项目短 seed、迁移保真、双档案冲突、活动锁、明确工作区优先与无系统依赖的独立安装。完整回归 183 项通过；辅助接口与安装包格式另做检查。历史验收中提到的旧拼写是当时实际行为，后续统一以本修复说明为准。
