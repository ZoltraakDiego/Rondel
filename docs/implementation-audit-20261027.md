# Rondel 实现审查：研究习惯、论文取舍与成果收尾

整体研究主线与项目发起者反复表达的习惯一致：先读来源与真实实现、广读后聚焦核心对象、有限改动与归因、保留用户自己的理解和路径选择。本轮核对发现，前期准备、实验记录与上下文控制比论文材料取舍和最终交付更完整，因此针对这两处补齐流程与文件能力。当前已登记 28 项工作流、七个本地辅助脚本，流程可用、文件验证、科学判断与对话体验分别评估。

## 审查依据与覆盖

核对了当前对话、仓库私有来源映射中有关实验、贡献中心与语言风格的人类消息，以及 Obsidian 中五份研究组织、实验与写作计划、正文证据核对、claim–evidence 和论文完成清单的相关部分。另读取论文、实验和研究笔记模板，了解既有属性、关联、个人判断与行动项的组织。历史笔记中包含 Agent 整理、归档结果与过期目标，本轮只将其用作工作方式的材料，没有重判历史科学结论、沿用旧截止日期或修改真实笔记库。

用户本轮进一步明确“先记录关键实验数据与 claim，最后统一整理笔记决定论文取舍”。该要求优先于旧笔记中的并行写作计划，已成为当前默认接续方式。外部来源只采用与实际缺口相关的建议，完整映射见 [研究与写作依据](../skills/rondel-main/references/research-writing-basis.md)，私有位置与读取摘要保留在本机忽略目录。

## 发现、取舍与修订

| 审查项 | 原实现及依据 | 本轮处理与当前边界 |
|---|---|---|
| 主线与研究者参与 | Main 已有核心阅读、用户摘要、保真复现、少量修正与归因，近期状态有来源 | 保留现有结构，明确已有解释直接接续，理解核对聚焦当前判断，避免反复口头考核 |
| 实验与证据 | 设置版本、方案范围、尝试预算和运行有效性分开，实际机器由宿主工具核验 | 保留；允许有限探索明确记录未知与观察目标，探索后提出的假设不冒充预先确认 |
| 论文材料取舍 | post.write 有章节与证据骨架，缺少最终统一整理笔记的覆盖、去向和理由 | 新增 paper_material_selection，分批审阅当前项目材料，保留主文、补充、研究档案、待核验四种去向 |
| 写作与表达 | 已有经典术语、条件明确的结论、主张证据与方法局限 | 补中心发现段落、章节连接、篇幅取舍与分轮修订；用户当前习惯优先，历史固定图数等不推广 |
| 研究交付 | 投稿准备只定位材料，普通 handoff 侧重暂停与 session 接续 | 新增 post.closeout、复现包与资料包模板、回顾与告别；接续现有记录身份和历史 |
| 提前结束 | records.PHASES 原先只允许 submit → archived，阻碍负结果或主动结束的收尾 | 各阶段允许沿真实用户选择归档，普通导出不改阶段；原始结果与未解项保留 |
| 文件导出 | 原先仅技能自身 ZIP 和笔记视图导出，尚无研究交付辅助 | closeout.py 按明确清单新建两份包，外部引用保持引用，保留文件摘要与旧交付；不执行研究命令 |
| 上下文与可见笔记 | 任务锚点、阶段摘要、历史查询和 Obsidian 可见视图已实现 | 沿有限任务范围接入新取舍与收尾记录；包内链接和附件仍需按实际交付核对 |

## 外部经验怎样采用

Simon Peyton Jones 的[写作讲义](https://www.microsoft.com/en-us/research/wp-content/uploads/2016/07/How-to-write-a-great-research-paper.pdf)支持明确核心想法和贡献到证据的对应，本轮将其用于最终材料组织。Neel Nanda 的[研究过程文章](https://forum.effectivealtruism.org/posts/hmBPqApDXvhLzbiFt/how-i-think-about-my-research-process-explore-understand)区分获取信息、检验假设和凝练交流，有助于解释阶段的不同目标；其框架作为经验参考。二者不覆盖用户当前的工作顺序，也不据此增加固定论文篇数、实验次数或理解评分。

Karpathy 的[训练经验](https://karpathy.github.io/2019/04/25/recipe/)与现有数据核验、可信管线和逐步实验方向一致，保留这一主线。NeurIPS 的[清单](https://neurips.cc/public/guides/PaperChecklist)为环境、命令、结果覆盖与材料获取路径提供具体参考，复现包据实际完成范围组织。具体投稿要求仍需使用时查当年正式来源，文件完整性和主要结果复现分别记录。

## 验证与尚待观察

新回归检查覆盖两份包的显式文件范围、原文件保持、旧交付编辑保护、目标越界、大小写冲突、缺失入口、外部引用不获取、任意阶段的归档来源和新路由上下文隔离。打包检查验证独立安装包含 closeout.py 和新增流程，完整结果见 [工程验收](VALIDATION.md)。隔离演示只使用合成文本与示例代码，真实科研模型、服务器、稿件与知识库均未修改。

仍需在实际项目中观察材料取舍是否抓住中心问题、覆盖记录是否忠实、研究者负担是否合适，以及告别是否自然。当前没有测得路由节省额度的比例，没有验证全部宿主操作，也没有将模板和单元检查当成这些体验的证明。后续依据具体失败修订，保持单一入口与现有记录合同，避免继续堆积职责和固定问答。
