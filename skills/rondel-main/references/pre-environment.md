# pre.environment：先定位资源，再建立环境

先恢复 [Pre 总表](pre-tracking.md) 的环境 Todo，按选定实现与目标机器初始化 environment 设置。已核验并采用的依赖锁、关键数值条件和环境定义冻结为版本，实际观测与可达状态单独保存。重建或修改依赖可能影响可比性时记录变更与对应结果，保持旧实验实际条件可追溯。

先通过 [资源聚合层](resource-aggregation.md) 明确本轮工作的机器、连接方式、代码、数据、环境与产物位置，不能默认实验发生在 Agent 所在机器。盘点系统、硬件、驱动、依赖管理方式、可用存储与配额；使用已有连接入口与环境事实，记录观测时间。资源清单用于筛选，执行前再核对实际可用条件。

建立依赖前先读选定论文的官方实现、版本、依赖文件、安装说明、配置和已有可用环境，列出与当前机器的具体差异。框架和硬件兼容性在当次操作中核对官方说明，不在技能中锁死通用版本组合。复用已有符合条件的隔离环境，或在约定位置建立项目环境，保持其他项目的使用方式。

按用户已经确定的建立环境范围执行，记录实际命令、依赖锁或导出、仓库与环境版本及必要变量名，认证信息使用现有凭据机制。涉及系统组件或影响其他项目的变更先形成具体方案，已有授权在原范围内沿用。远程路径保持目标系统的语义，不能在本机解析为实际目录后再下发。

环境验收分清依赖安装、导入检查、设备可见性、数据入口可读和模型级验证，各自记录范围与证据。导入成功或一次前向不代表论文复现完成，训练与正式评价进入对应实验任务。失败时保存日志和已知差异，避免反复重装或静默换仓库、依赖和协议。

使用 [环境卡](../assets/templates/environment.md) 保存 `resource`、`purpose: environment`，关联机器、代码来源与数据卡。交给 Main 时给出可用入口、已经验证的能力、尚缺条件与下一项建议，环境和大型缓存留在所绑定机器的约定位置。
