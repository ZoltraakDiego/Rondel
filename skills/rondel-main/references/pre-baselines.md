# pre.baseline：读完核心论文再选基线

本职责统一命名为 Baseline，评测套件或评价集合另用其实际名称。先恢复 [Pre 总表](pre-tracking.md) 的 Baseline Todo；选定对象后将来源、提交、配置、检查点和实际配方初始化为 baseline 设置，核验并确认冻结。改变核心实现或配方时建立关联版本，具体复现结果固定原版本并进入影响审阅。

正式选基线之前先核对当前任务、已读核心论文卡、研究者自己的理解和数据评价协议草案。若这些依据不足，先补对应阅读或协议缺口；候选代码可以用于理解，但不能因为易运行就自动成为研究基线。用户已有充分阅读与复现记录时直接接续这些证据。

建立少量候选对照，比较问题相关性、输入与监督、训练及推理条件、原论文证据、官方代码版本、数据和资源可得性。推荐最贴近任务且实现与证据可核对的强对象，说明保留其他代表方法的理由。任务不同的最高分、第三方榜单或单一工程速度不能独自决定选择。

对选定对象逐项核对论文到真实数据流、配置、损失、采样、状态与推理的对应，区分可以直接沿用的部分、接口适配与核心改变。保留核心语义，必要改变先展开讨论，并给出匹配验证范围。复现完成标准在具体方案中明确，工程跑通、局部检查、部分复现和完整匹配复现各自保留范围。

使用 [基线选择模板](../assets/templates/baseline.md) 保存 `discussion`、`purpose: baseline_selection`，关联核心阅读、协议与实际选择来源。随后在选定机器建立相应环境，补齐基线特定配方，并创建具体复现实验方案。正式来源结果与本项目复现结果分开，复现偏差返回数据、实现和协议核对，而不是直接归因为模型思想失效。
