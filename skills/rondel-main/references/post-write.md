# post.write：从主问题与证据形成连贯论文

先接续实验期已经记录的关键数据与候选 claim，在收尾组织论文时按 [笔记取舍](paper-material-selection.md) 统一审阅当前项目笔记，确定哪些进入主文、补充材料、研究档案或待核验集合。读取当前中心问题、收敛版本、入选主张、真实图表和已有稿件，组织问题、已有局限、关键想法、挑战、方法与证据的逻辑。研究者已有的口述、摘要和实际选择直接接续，Agent 提供具体组织稿，仅围绕影响取舍的缺口提问；具体章节请求不要求重走整轮研究。

沿 [论文模板](../assets/templates/manuscript.md) 保存 purpose: manuscript，使用完整段落和经典技术术语，保持章节之间的因果与证据关系。实际实现、训练与冻结条件、数据、监督和推理范围与源码及设置对应，数值和引用逐项回到来源。尚未完成的事实放入独立待补证据记录，草稿只写当前材料支持的内容，不代填结果、作者信息或 DOI。

必要方法边界放在影响解释的位置，局限不变成反复防御，完整探索细节留在研究记录。引用依据正式论文页、作者版本与实际核验内容，目标格式和最新投稿要求在用到时查官方来源。原稿和研究者编辑原地保留，改写不改变技术含义，重要重组说明对应理由。

先将入选内容凝练成一个中心发现段落，再为章节和段落分配各自回答的问题、所需证据及前后连接。Results 按当前问题和可支持的主张组织，同类观察合并，长推导、详细诊断与复现信息放到合适位置。主文的图表与篇幅预算结合实际目标共同确定，历史某篇论文的一表一图或特定数据集安排不成为所有项目的固定门槛。

需要 PDF、LaTeX 或其他文档产物时使用当前可用工具核对保存文件、编译诊断或实际渲染，未成功的步骤说明当前完成范围。交给 post.submission 的是当前稿件与图表版本、已核对来源、中心证据和有限待补清单。用户只请求讨论时保持草稿在当前允许范围，实际写入沿其位置与格式要求。

初稿后沿“技术含义与证据、章节连贯与必要性、语言和重复、引用数值与实际渲染”修订，回到来源核对实质变化。新反馈优先通过替换、合并或移到补充材料解决，新增内容说明它改善哪项判断。作者指南和实际披露要求在使用时核对，完整研究日志继续留在资料包入口。
