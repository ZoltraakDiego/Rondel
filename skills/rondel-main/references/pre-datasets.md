# pre.data：找数据集与核对样本

进入该项时先恢复 [Pre 总表](pre-tracking.md) 的数据 Todo、领域痛点与主问题。实际选用的数据按用途初始化 dataset 设置，定义固定来源、内容与清单摘要、标签和划分，核验后沿实际选择冻结；未知项保持草案。版本变化先审阅受影响的运行、分析与结论，再更新当前准备状态。

从已读论文的任务与协议出发整理数据需求，查已有数据位置、论文数据页、官方项目、正式仓库或维护方的数据卡。比较任务、输入模态、样本单位、标注粒度、类别、群组划分、许可与访问条件，记录来源版本与实际可获取方式。官方来源与第三方镜像分别标明，候选数据不能直接作为已可用资源。

先登记数据在哪台机器、什么位置、由谁维护及当前核验状态，再在选定范围内获取或读取。核对清单、数量、标注文件、类别映射、样本标识与版本摘要；抽查具体样本和标签如何对应时间或空间单位。确认原始视频、预提取特征、下采样与标签时轴的关系，保留无法核对的条件。

训练、验证、测试与支持、查询等划分按当前任务和官方协议逐项核对，特别检查视频、主体、任务、类别等分组是否跨边界泄漏。哪些维度需要互斥由所选研究设定决定，不能把不同论文的划分拼成一个“标准”协议。测试集使用范围、模型选择与调参来源在 [协议](pre-protocol.md) 中明确。

使用 [数据卡模板](../assets/templates/dataset.md) 保存 `resource`、`purpose: dataset` 记录，关联论文、机器、数据版本与核验产物。资源处于 `recorded` 时只说明已经登记，实际核对后才能按证据更新为 `checked`。完整数据与大产物保留在机器绑定位置，`.rondal/` 保存清单、摘要、来源和状态。

交给 Main 的结论应说明哪些数据适合当前任务、哪些条件已核验、哪些仍影响比较，以及下一项最小检查。数据暂不可得时可以提出合法替代候选与差异，研究者采纳后再调整协议与计划。
