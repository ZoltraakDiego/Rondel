# mid.implement：在明确范围内落实实现

先读实际源码、用户当前任务、方案与来源对应，定位输入输出、状态和接入点，再做最小必要修改。具体代码请求已有明确范围时直接处理，普通修复不强制重新初始化或重新批准整项研究。研究机制变化仍关联假设、成熟实现和方案，执行范围与代码编辑范围分别保留。

保留沿用模块的数据流、采样、门控、归一化和训练推理语义，接口适配和核心变化分别说明。按实际改动做必要且有区分力的检查，例如形状、梯度、边界重置、状态时序、匹配输入回放或评价入口；不用镜像实现的测试堆积检查数量。训练或真实评价由具体运行范围决定，工程检查的通过不表示假设已经获得证据。

purpose: implementation_note 的 discussion 使用 [实现与核对记录](../assets/templates/implementation-note.md)，保存源码版本、具体差异、来源对应、检查命令和产物。原有用户修改保留，发现并行编辑先重读而非覆盖。向 mid.preflight 返回当前实现、实际已检查范围、必要差异和剩余条件，向 Main 返回它是否仍服务当前问题。
