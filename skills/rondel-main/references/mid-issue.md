# mid.issue：从现象形成值得检验的问题

读取当前主问题、相关预测或原文、实际条件和最近分析，先描述发生了什么、影响哪个目标，再整理可能解释。输入可以是一次失败行为、局部指标分歧、作者明确的局限或研究者的疑问，来源和确认程度分别保留。目标是明确一个能被证据改变的判断，不先指定必须增加的模块。

核对现象是否来自有效运行、协议变化、实现错误或目标条件；没有产物时以待验证观察处理。将问题写成对象、条件、行为与影响，候选机制写为 hypothesis，说明什么证据会支持、削弱或仍不能区分它。用户已经明确的优先级直接采用，关键取舍有真实来源。

question 通过正常状态记录 clarified、active 或 parked，hypothesis 从 proposed 到 testable 按材料充分程度更新，选中假设需要实际用户来源。完整讨论使用 purpose: research_issue，关联痛点、主问题和证据，正文采用 [问题与机制来源模板](../assets/templates/research-issue.md)。交给 mid.retrieve 的内容是当前问题、候选解释和最需要查证的缺口，交给 Main 的是本轮为何优先。
