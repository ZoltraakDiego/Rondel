# 交接与暂停

用户要求完整研究收尾、复现包或资料包时按 [post.closeout](post-closeout.md) 完成交付与回顾。普通暂停和 session 交接仍使用本流程，结束交付不自动等于暂停或归档。已有 Mid/Post 退出评审与阶段文档保留实际选择、带入项和首项任务，恢复时直接接续相应入口。

任务转换涉及 session 建议时按 [边界与接续规则](session-boundaries.md) 准备专用交接包。新会话只带当前目标、有效范围、阶段摘要与必要来源，当前会话保留为历史；提出建议本身不创建新会话，也不把研究项目标为暂停。用户已明确要求新开时沿实际宿主能力落实，不重复确认同一选择。

已经进行 Pre 退出评审时，交接保留推荐与实际选择、正常或提前进入的条件、评审和决定引用、带入任务及首项中期工作。有限补齐仍在 prepare，写明补充产物与下一检查点；进入中期后恢复直接定位已选择的任务。记录中的阶段和实际运行范围分别核对，避免恢复时重复整轮评审或自动启动研究任务。

交接包含当前问题、共同确认的认识、用户决定、候选解释、未解分歧、证据位置和实际工作状态。描述运行任务时核对已有产物、清单和当前进度，区分准备、验收、训练、评价与分析。研究者的修正放在易恢复的位置，历史细节通过链接定位。

同时保留当前计划位置、阶段剩余条件和约定评审点，关联重要的核心阅读、用户摘要、复现与思考承诺。近期理解、精力与阻碍只保留影响下一轮的必要信息及来源，恢复时结合新表达核对，临时状态与长期画像分开。曾经触发停滞评审时记录采取过的调整，下一轮检查行动是否改变了当前缺口。

一次项目可以有多个历史交接，默认路由优先定位服务当前阶段的已审阅阶段文档，再按本轮相关性接入 current 交接；没有阶段文档时以相关交接补充。旧交接作为历史保存，需要时明确查阅，原 context 兼容定位仍返回最新 current 入口。恢复不根据旧摘要自动创建队列或重复运行任务。

用户暂停时，记录 paused 并停止新增推进；在跑任务按当次指令处理，已有进程不会因笔记字段变化自动停止。后续恢复核对用户意图、未完成清单和实际产物。明确的继续请求沿用仍有效的原范围。
