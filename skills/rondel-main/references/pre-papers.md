# pre.library：找论文、阅读与实现定位

检索从 Init 的 search_summary 与当前核心问题展开，结果回到 [准备总表](pre-tracking.md) 的领域地图和核心阅读 Todo。每条主要路线应说明它回应哪项痛点，哪些局限有来源、哪些仍是猜想；关键新证据出现时更新对应问题与优先级。核心集合具备选择依据后收拢阅读，不无限增加待读任务。

先查用户指定论文库与已有卡片，提取任务名称、同义词、上位领域和相邻机制关键词，再选择当前可用的学术检索工具。优先核对正式论文页、作者主页、出版社或会议论文库、预印本与作者维护仓库，搜索结果和第三方介绍用于定位。检索记录查询式、来源、日期、纳入与排除理由，保留经典路线、近期强工作和跨领域启发。

以 DOI、正式标题、作者、年份与版本去重，区分预印本和会议版本。逐篇核对研究问题、输入与监督、训练与推理、数据与评价协议、核心证据、局限和实际代码入口。遇到全文无法访问或细节仅见二手转述时保留缺口，不能代填已核验结论。

广读结果形成领域地图，再依据目标相关性、证据、思想代表性、强度与复现可行性推荐少数核心论文。对核心对象按原文位置精读关键图、公式与实验，检查真实代码调用，邀请研究者用自己的话概括和提出疑问。AI 已读、用户自述、用户自己的摘要和共同讨论的理解分别记录，代码链接存在不代表已完成复现。

使用 [检索日志](../assets/templates/literature-search.md)与 [核心论文卡](../assets/templates/core-paper.md)。检索日志可为 `discussion`、`purpose: literature_map`，核心卡为 `discussion`、`purpose: core_paper`，将实际来源与用户摘要关联。阅读完成后交付方法路线、数据与资源要求、候选局限和可复现性判断，再进入 [基线选择](pre-baselines.md)；未读懂的核心候选继续作为候选。

下载全文采用合法可用来源，已有材料留在原处并绑定。搜索与论文核对可在当前请求范围内连续推进，新增大规模收集或外部动作按实际需求和权限处理。没有明确领域时，先形成一轮有范围的覆盖地图再与 Main 收拢，避免无限扩大待读列表。
