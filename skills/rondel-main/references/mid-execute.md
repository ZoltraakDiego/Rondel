# mid.execute：执行已经确定的有限清单

读取 approved 方案、冻结 scope 与 setting_refs、当前 preflight 和真实机器状态，沿已确认范围执行。每个条件使用稳定 run_key，每次尝试有独立 run；记录 experiment_ref、attempt、设置引用、目标 host_id、代码与配置、命令或调度标识、日志和产物位置。模式选择、路由结果或结构检查不会单独启动运行，真实提交由当前可用终端、SSH 或调度工具完成。

提交前核对是否已经排队、运行或产生产物，已有 planned/ready 记录直接接续而不再建重复尝试。有限范围与尝试次数用 [结构检查](evidence-helper.md) 辅助核对，失败保留原 run，重试只在相应预算和实际选择内进行。未指定重试默认不重试；需要新增条件、种子、数据或预算时先形成可审阅调整。

queued、running、completed、failed、cancelled 按实际证据分别记录，completed 只表示该次进程结束。异常先定位具体日志、输入与环境差异，已获准的修复沿原范围完成；不能静默换模型、数据、监督或协议后仍归为同一条件。中止和暂停依据当次明确指令或适用的预先约定，不操作无关服务。

长任务用已有任务标识接续，阶段更新只在有意义变化时报告；用户明确要求会话外监控时才接入实际可用的跟进能力。运行结束向 mid.inspect 返回实际清单、退出证据、完整产物入口与偏差。Agent 不将进度估计或旧进程号当成实时完成证明。
