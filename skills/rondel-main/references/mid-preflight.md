# mid.preflight：核对这次实际将运行什么

先读取冻结方案、实际运行清单、代码与配置、设置版本和目标机器，核对本次是否仍在已确认范围。使用 [执行前模板](../assets/templates/preflight.md) 保存 purpose: preflight 的 discussion，再以 [evidence.py](evidence-helper.md) 做本地结构检查。结构结果只覆盖记录、引用和有限清单，真实依赖、数据、设备、代码版本与入口通过当前工具核验。

检查实际配置与计划一致、运行标识唯一、已有任务和产物未被重复提交，代码提交、数据内容、预处理、采样、评价与选点入口有来源。核对所选机器的观测时效、空闲资源、配额和产物位置，远程路径保持目标系统语义。通过 snapshot 保存必要本地来源摘要，远程事实以实际连接或调度证据关联，不把本机路径解析当成远程核验。

只对会影响正确性、有效比较或当前范围的真实问题暂停该项，已知无关告警按项目约定处理。发现冻结条件改变时关联新版本和影响审阅；记录错误、资源等待与科学假设分别归因。已经获准且条件一致的任务核对后继续，不为每个机械步骤重复询问。

实际核验完成后按证据将 experiment、run 更新到适用的 preparing/ready 状态，核验笔记引用实际设置和产物。还缺哪项条件就保留哪项，不能仅凭本地 structural_ready 将远程执行标为就绪。随后交给 mid.execute 的是有限清单、当前证据和仍有效的范围。
