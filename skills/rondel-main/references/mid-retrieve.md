# mid.retrieve：定位最接近的成熟来源与真实实现

从当前具体问题与候选机制出发，先查项目已读论文和实现记录，再检索正式论文页、作者仓库、配置与真实调用链。与 pre.library 的领域覆盖不同，这一步要回答某个已有实现怎样处理当前问题、哪些部分能直接沿用、它在哪些条件下不适合。来源缺失时如实保留，不将论文图或基础算子引用当成实现对应。

固定来源版本、许可、原配置和模型状态入口，核对输入输出、数据流、采样、损失、状态更新、归一化、激活、选择与融合、训练和推理语义。优先只适配形状和接口；必要核心变化说明原作用、具体差异、理由和对应验证。来自成熟模块的有效证据与本项目局部工程检查分别记录，不能把简化实现的结果解释为原方法复现成绩。

使用 purpose: method_source 的 discussion 与 [实现来源模板](../assets/templates/method-source.md)，关联正式来源、实际文件或符号、版本和候选方案。研究者解释这份实现与当前假设的关系，Agent 准备调用路径和差异对照。完成后向 mid.design 或 mid.implement 返回可复用对象、接口边界、未核对条件及最小必要验证；未采纳对象仍为候选。
