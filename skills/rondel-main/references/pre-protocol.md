# pre.protocol：数据、评价与基线配方

按 [前期跟踪](pre-tracking.md) 恢复当前协议 Todo 与版本，将选定的数据、监督、适配、模型选择和评价条件初始化为 protocol 设置。核验并采纳后冻结，后续方案与运行固定该版本；已冻结条件的修改建立关联草案并记录旧结果影响。共享协议与各 Baseline 的原始配方分别关联，避免在复现过程中静默改变比较条件。

先根据当前问题、已读论文和数据卡形成数据与评价协议草案，明确输入、监督、样本单位、划分、模型选择与指标。协议中的每项关键选择注明来自哪篇论文、官方实现、数据说明或用户决定。无法对齐的设定分别记录，保留其影响，不用一个无来源的默认配方代替核对。

数据协议写清预处理、采样、特征来源与版本、标签对齐、可用类别与数据边界、训练及测试时各自可见的信息。少样本任务进一步明确支持与查询构造、样本数、类别与任务划分、适配允许使用什么，以及验证和测试访问范围。因果或在线条件覆盖特征提取、状态更新与输出，不仅核对最后一层的掩码。

评价协议写清指标定义、聚合单位、背景与无效样本处理、选择模型的依据、调参来源及结果汇总方法。原论文报告、本项目复现、工程试验与新方法结果分别标记来源。对照比较明确数据、输入、预算与允许变化，关键差异单独说明，避免未匹配的结果进入同一归因结论。

核心论文读完并选定基线后，再核对该官方实现的损失、优化、调度、初始化、检查点与推理配方，作为基线特定附录关联。共享数据与评价条件和各方法原始配方分开管理，必要改动先说明来源与影响。协议经用户选择形成当前版本，实验开始后使用对应冻结版本，变更保留旧版与受影响比较。

使用 [协议模板](../assets/templates/protocol.md) 保存 `resource`、`purpose: protocol`，关联数据、论文、环境与决定记录。脚本的资源 `checked` 仅表示有对应核验，科学可比性由 Main 结合实际来源判断。交付给基线选择与实验方案的是明确版本、已确认条件和仍阻止比较的缺口。
