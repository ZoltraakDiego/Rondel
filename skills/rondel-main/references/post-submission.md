# post.submission：按真实目标核对投稿材料

先明确用户当前选择的投稿目标、年份、文章类型与实际稿件，不把历史候选当成当前决定。核对官方作者指南、模板、摘要与全文等不同节点、截止日期及时区、篇幅、匿名、文件和实际必需声明。保存正式来源 URL、核对时间和对应版本，未知或冲突条件明确保留，排期结合用户投入与必要缓冲。

purpose: submission_requirements 的 resource 保存实际要求与已核对条件，purpose: submission_package 的 discussion 使用 [投稿准备模板](../assets/templates/submission-package.md)。关联稿件、图表、引用、补充材料、代码数据入口、目标格式和当前文件摘要，审阅主张证据及方法边界是否与材料一致。实际研究涉及哪些统计、数据、作者或披露要求就核对对应项，不机械增加与目标无关的材料。

先把本地准备做成具体可审阅的包，检查实际导出与格式并保留原始编辑源。准备、导出、系统上传、正式提交和收到回执分别记录；只有本地文件不能推断已经投稿。用户没有选择外部提交时完成准备稿，已经明确授权具体目标和最终材料的动作沿原范围落实，不重复询问同一选择。

外部系统使用当前实际可用工具与权限，无法接入时提供完成的材料、位置和操作清单，说明尚需哪一步。新要求或稿件变化时核对受影响内容并保留旧版本，阶段选择与外部动作范围分开。Main 保存真实决定、提交证据与后续入口，跨阶段按文档和 session 规则接续。

用户要求结束本轮研究或交付完整材料时接 [post.closeout](post-closeout.md)，整理复现包、资料包与实际验证范围，再回顾和告别。正式投稿后的修回或后续工作保留对应任务入口，交付本身不表示已经接受、发表或归档。
