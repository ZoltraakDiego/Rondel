# 阶段上下文：沉淀、归档与接续

阶段划分同时服务研究组织与上下文管理。每个阶段结束时，保留能够独立接续下一阶段的文档，而不是把全部对话、尝试与日志重新注入。阶段文档组织下一阶段必需的信息，原始来源继续保留，完整性由实际覆盖与共同审阅核对。

## 一份阶段文档应留下什么

按 [阶段模板](../assets/templates/phase-summary.md) 保存领域与主问题、用户自己的关键理解、当前认识及其条件、真实决定、固定设置、未解问题、带入任务和首项工作。研究认识分别标记 observation、hypothesis 或 reviewed，并关联实际证据；用户决定只引用真实 recorded decision。未确认解释、负结果的适用条件和仍然影响比较的差异随文档保留。

正文可完整展开，另在 brief 中留下短小的结构化导航。brief.question 明确主问题，findings 给出条件和证据，decisions 指向真实选择，open_questions 和 carryovers 留下未解事项，next_step 指明首项工作。设置使用 setting_refs 固定版本与定义摘要，source_snapshots 保存所引用记录的版本和字节摘要。

文档使用 discussion、purpose: phase_summary，summary_of 表示来源阶段，summary_for 表示服务的阶段。初稿为 open，核对来源和实际用户审阅后通过 publish 进入 recorded，reviewed_by 保留真实来源。已审阅文档封存，新的认识进入新草案，旧版仍可定位。

## 临时信息与过去方向怎样归档

set_visibility 使用独立的 context_registry 保存 active、archive 或 temporary 及理由。它只改变默认加载和活动索引，不移动或改写原论文卡、方案、设置和结果，也不把方向的科学状态改成失败或已放弃。原文件的摘要、冻结设置与旧结果引用保持稳定，归档后仍可按名称或引用查询。

活动集合保留当前主问题、有效决定、实际采用的设置、正在做的任务和相关证据入口。已经结束且结论已沉淀的细节、被明确暂存的方向和阶段内临时推演进入归档或临时区。下一阶段仍依赖的工作与带入项保留活动入口；归档范围根据实际任务确定，不按文件时间一刀切。

## 阶段沉淀的顺序

先沿当前计划整理阶段认识与实际来源，明确哪些事项带入、哪些只需要历史入口。更新上下文归档导航后再建立摘要的 source_snapshots，归档不会改原记录，因此也不会令已有证据摘要失效。随后展示阶段文档与下一步，沿用户已表达的审阅或采纳范围发布；同一次阶段选择已经覆盖这些内容时直接接续，避免增加重复确认。

生成和发布文档不会更新 phase。实际进入下一阶段仍由决定和 configure 完成；当前仅设计路由或暂不转阶段时，可以准备草案，不推进真实研究。phase_summary 按 summary_for 生效，未来阶段的文档不会提前替换当前阶段上下文。

## 下一轮只加载相关部分

正式阶段转换时，Main 主动评估是否建议从新 session 接续，先按 [session 规则](session-boundaries.md) 准备阶段文档与首项任务的接续包。用户已经采纳包含新会话的具体安排时直接落实，仅改变阶段或保存摘要而未选择新会话时保留当前会话。新的 session 默认使用空白上下文加精简交接，研究阶段和执行范围仍按实际决定保存。

默认选择当前阶段最近一份已审阅且活动的阶段文档，普通恢复或复盘读取其 brief，数据等专项任务只取问题与下一步。原正文、其他认识和证据从 navigation 按需展开；没有阶段文档时，回到精简 Init、当前任务与相关交接。过时阶段文档与原始历史不会自动进入普通请求。

来源记录变化或被引用设置有新的冻结版本时，上下文包标记需要复核，并保留摘要位置而不内联旧判断。Main 按变化范围回到具体证据，修订或重新发布阶段文档，旧结果继续保留原条件。这样的变化提示是导航检查，科学有效性仍取决于实际材料。
