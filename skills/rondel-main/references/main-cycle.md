# Main：沿当前计划推进与复盘

恢复先按 [本轮路由](router.md) 加载当前阶段摘要与相关任务包，沿导航读取当前计划及证据。需要回到旧方向时显式检索归档，完整历史交接只在相关问题需要时展开。阶段收束按 [阶段上下文](phase-context.md) 保存下一阶段所需信息和带入项，后续恢复以该文档与当前用户修正接续。

Main 从用户认可的理解与计划接续，研究主线是广读优秀论文、选择少数核心工作精读与复现、形成用户自己的摘要与思考，再围绕具体局限做少量修正和归因。每轮同时理解研究证据与用户当前状态，选择一个真正推进的任务，核对产物、共同解释结果并更新计划。先读用户当前请求与 `.rondal/` 中的 Init、索引、相关计划和复盘，已有第一步时沿用其目标与范围。

整体关系见 [Main 流程图](main-flow.md)，其中把研究阶段、用户状态、复盘、停滞调整和下一轮接续放在同一张图中。具体任务到工具职责及其回传关系见 [工具映射图](main-tool-map.md)。

阶段安排、论文选择与转移条件读 [研究主线](main-research-loop.md)；用户理解、精力、阅读承诺或停滞影响推进时读 [状态与推进](main-state-and-momentum.md)。两者分别回答“研究应往哪里走”与“这轮怎样帮助用户实际走出一步”，普通状态查询按相关性加载。

## 从 Init 进入

Init 交付一个完整的理解段落与推荐计划，用户修订后，Main 接收当前任务、预期产出、计划位置和复盘节奏。计划尚未认可时，在已有建议上完成必要修订；用户已经说“按这个开始”时直接记录并接续。用户只是询问“接下来是什么”时，说明现在走到哪一步、为什么推荐下一项，以及它会带来什么具体产出。

Main 的七个模式分担入口、状态、复盘、决定、配置和交接，无需在每轮逐个调用。它协调研究主线，具体操作使用当前实际可用的检索、文件和执行工具；其他集合的能力状态见 [roadmap](roadmap.md)。

## 先判断研究状态与用户状态

在 prepare 阶段按 [前期跟踪](pre-tracking.md) 读取准备总表与本轮相关的 Todo，定位当前核心痛点、主问题和正在使用的设置版本。新论文、实际数据或用户修正改变了判断时，更新对应焦点与来源；修改冻结条件先建立版本并审阅结果影响。普通状态查询保持只读，完整 Pre 的初始化只执行一次并在恢复时接续。

核对当前阶段、最近实际推进、阶段退出条件与评审点，同时接续用户最近表达的理解、困惑、时间和精力。只核对影响本轮安排的变化，观察、推测与用户自述分别保留。用户尚未理解核心论文时优先安排相关原文、图与实现的共同分析；阶段证据已满足时主动提出转阶段建议。

Main 主动跟进用户已认可的阅读、思考与尝试承诺，AI 摘要不能代替用户实际阅读与自己的解释。阶段评审点到期或连续两次约定复盘缺少实质推进时，按 [状态与推进](main-state-and-momentum.md) 触发调整，次数可以随协作约定修改。每次触发都需要新的行动或明确取舍，正常等待与单纯状态查询单独识别。

## 本轮工作：问题、产出与范围

主要意图变化后，Main 按 [轻量路由](subagent-router.md) 获得并校验分类，在大量读取新资料前按 [session 边界](session-boundaries.md) 主动评估是否建议新会话。建议前先整理可审阅交接，用户选择继续则保留当前 session 并加载本轮小型任务包。普通追问与同一问题下的职责切换保持连贯，不重复提醒。

从当前计划选出一个能推进研究认识的具体任务，说明它要回答的问题与应留下的产物。文献任务定位相关论文、真实实现及差异；代码任务明确输入输出、接入点与对应验证；实验任务关联具体方案、协议、资源和范围。用户的当前要求可以调整优先级，实际决定通过 [决定记录](decisions.md) 保存。

核心工作留出用户自己的阅读、摘要、机制解释与局限判断，AI 准备原文、定位实现并处理可重复部分。每轮说明用户最小行动、AI 配合、具体产物与复盘点，按当前投入调整任务大小。文献广度、核心理解、复现证据与修正归因都有对应产物，任务优先级依据当前阶段真正缺少的部分选择。

已经批准的任务在范围与条件保持一致时继续完成。新方向、额外运行或预算变化影响研究安排时，先给出有依据的调整建议，再沿用户实际选择推进。概念性计划、工作粒度偏好和历史自动消息各自保留来源属性。

## 核对产物与形成认识

读取实际论文段落、实现、配置、报告或预测结果，核对本轮产出是否回答了当前问题。实验结束后先确认运行条件和产物，再看主要指标、行为变化、收益损伤与替代解释；记录检查结果、观察和候选解释各自支持什么。只在会影响结论或下一步时扩大读取范围，旧日志与进程号用于定位，实时状态以当前证据为准。

出现实现错误或无效运行时，保留记录并按已有范围处理，科学解释依据有效证据形成。发现实际协议与计划不同、关键材料变更或资源不可用时，说明这会改变哪项比较或排期。技术判断先核对来源与调用关系，相关主线变化使用 [复盘流程](drift-check.md)。

## 按用户节奏共同复盘

用户偏好逐实验复盘时，每个实验结束后用连贯段落解释做了什么、看到了什么、对当前问题意味着什么，并给出下一步建议。用户认可有限清单连续推进时，按其范围执行并在约定检查点汇总。普通资料整理与已有范围内的修复沿用实际约定，避免把每个机械步骤都变成新的选择题。

提问聚焦会改变判断或安排的一个关键选择。用户明确采纳、调整、暂存或停止时，保存实际来源，再更新相关对象。只请求状态时直接说明当前阶段、最近完成的产物、已知的当前困难、阶段剩余条件和当前下一步，按需要附证据入口；只读请求保持只读。

## 更新计划，接续下一轮

prepare 阶段收束时读 [Pre 退出条件与交互](pre-exit.md)，依六项条件给出整体判断、关键证据和首轮任务。评审结果区分进入中期、有界补齐、调整问题与明确暂停，带入项保留真实状态和复盘点。实际用户选择保存后更新阶段、计划与 next_step，阶段转换不自动创建实验运行。

investigate 收束时读 [Mid 到 Post 转移目标与交互](mid-exit.md)，核对候选发现、有效比较、归因、可接续版本、用户理解与有限清单。先推荐进入 converge、有限补齐、调整或暂存、暂停中的一项，并给出首项收敛任务。保存实际评审与选择，沉淀阶段文档后接续，进入 write 的条件继续单独核对。

每轮把重要观察、候选解释和用户决定保存到 `.rondal/` 的相关记录中，更新当前计划位置、任务状态与 `next_step`。阶段结束或资源、目标变化时，说明哪一段计划需要调整、依据是什么，再保存修订版本和对应选择。计划粗略部分随证据细化，当前阶段需要具体产出与复盘点。

转阶段复盘列明已满足的证据、仍影响下一阶段的缺口和推荐动作；前中后期条件以 [研究主线](main-research-loop.md) 为准。阶段预算触发评审，阶段条件由真实材料核对，变更沿用户实际选择或仍有效的条件性决定保存。新的旁支留在外围集合或暂存状态，回到前一阶段时明确补什么、何时返回。

完整计划使用带 `purpose: research_plan` 的讨论记录，用户采纳与关键修正另存决定；`next_step.plan_ref` 指向当前计划，相关引用加入项目的 `refs`。更新正文使用 `configure` 的 `body`，省略时保留已有正文。脚本只保存与核验记录，实际工具执行及监测安排依据当前任务。

暂停或交接时按 [handoff](handoff.md) 保存当前问题、计划位置、已完成产物、有效范围和待续事项。恢复先核对变化，再回到本轮工作循环。用户明确结束模拟、转回技能设计时，切换到其当前请求；模拟中的研究内容作为设计评估材料，不继续推进研究任务。
