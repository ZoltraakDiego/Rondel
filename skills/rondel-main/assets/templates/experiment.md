# 实验方案

## 本轮问题与共同理解

用一个连贯段落说明为什么做这次实验、它对应哪条论文局限或实际观察，以及结果将改变什么判断。关联用户当前选择、基线与来源。

## 假设、预期结果与否证条件

写清可检验假设、预期行为和削弱解释的结果，实验批准所需的 hypothesis、expected_result、falsification 与 scope 字段由实际方案同步填写。

## 本次要区分的解释

说明核心修正与替代解释，并给出最有区分力的对照。容量、输入特征、训练量、接口或监督变化与目标机制分别核对。

## 数据、对照与训练协议

用 setting_refs 固定实际使用的数据、协议、Baseline 和环境，包含记录引用、设置版本与定义摘要。已批准后保留这些引用，设置变更后的新实验使用新方案或明确的新条件，原运行继续关联旧版本。

关联冻结的数据与评价协议、基线特定配方、代码与版本、初始化、随机性、选点与评价入口。每个比较条件与允许变化明确记录。

## 主要指标与行为诊断

同时定义总体表现、收益与损伤、关键类别或条件、行为诊断、资源代价和汇总单位，来源与统计口径可定位。

## 资源、运行清单及范围

scope.run_keys 固定有限运行标识，max_attempts_per_run 与 max_total_attempts 明确登记的尝试预算，未指定重试默认一次。每个运行保存 experiment_ref、run_key、attempt 与 setting_refs，已登记的待运行或活动任务直接接续。required_setting_purposes 按本方案实际条件确定，不适用项有来源与理由。

| 条件或运行 | host_id | 代码、数据、环境与产物入口 | 预算与范围 | 完成和异常判断 |
|---|---|---|---|---|

远程路径使用所属系统语义，记录实际连接或调度入口。具体运行分别建立 run 记录，禁止以资源清单替代当前可用性核验。

## 结果将怎样影响下一步

说明支持、削弱或仍无法区分解释时分别如何安排，约定用户与 AI 的分工及复盘点。批准后的方案保持冻结，实际运行与分析关联独立记录，不把后续结果追加改写为原计划。

## 研究者判断与 Agent 回写

聚焦本轮最需要研究者思考的一处，保留其实际解释、疑问或选择。AI 回写对应依据、方案修正与待办，采纳与执行范围关联真实决定。
