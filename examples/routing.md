# 模式识别、按需上下文与阶段归档案例

新意图先由轻量路由 subAgent 分类，主 Agent 校验后再准备本轮上下文；模型偏好和调用约束见 [协议](../skills/rondel-main/references/subagent-router.md)。下面的语义结果是预期行为，确定性脚本检查与真实模型试用分别记录。进入新 session 的判断由 Main 结合任务边界完成，不交给只看短提示的路由 Agent。

这组场景展示 Agent 应如何选择模式，以及脚本实际负责哪些确定性部分。项目阶段、记录名称和引用均为虚构设定，实际使用需要当前档案与来源。完整合同见 [路由](../skills/rondel-main/references/router.md) 和 [阶段上下文](../skills/rondel-main/references/phase-context.md)。

## 请求含有多个信号：以当前意图和范围为准

你说：“先别实验，只看一下现在用的协议，尤其支持集和查询集有没有混。”Agent 选择 pre.protocol，保留只读范围，指定当前协议引用；不会因为“实验”一词加载运行清单或启动执行。packet 提供领域摘要、当前主问题、协议卡和路径，正文与实际划分代码等这项核对需要时再读取。

最终回应应解释实际核对的条件、证据和仍未明确的边界，原计划中的运行状态照实保留。若你接着说“先修改协议，再看哪些结果受影响”，Agent 将任务排为协议修改与 Main 复盘，先完成当前一步。后一个模式与原始日志不提前全部注入，执行仍沿实际方案与范围。

## 后期也可以找论文：phase 不能覆盖意图

假设项目已经在 write，你说：“帮我找一下这个机制有没有更直接的相关工作。”主要模式仍是 pre.library，当前阶段用于筛选相关证据。packet 只提供必要问题、当前任务、论文地图或目标卡，阶段文档也只取问题与下一步，不展开整个前期档案或论文草稿。

找到资料后再说明它是否改变当前论证或只是补充背景。若确实影响某个主张，下一项工作可以进入 main.review，读取对应主张与证据。新论文不会自动改写方向或重新开启整轮 Init。

## 独立问答与项目核对不同

你说：“解释一下 F1 的含义。”当前只需要独立概念解释时，模式为 general，不读取项目画像或实验记录。你若说“我们这份报告的 F1 具体怎么计算”，才进入 pre.protocol 或 main.review，定位实际评价实现和报告。

模式由语义与上文共同判断，名称中包含研究术语本身不意味着需要完整项目。脚本测试能够验证 general 没有读取档案，不能单凭该测试证明所有自然语言都已正确分类。实际交互仍按当前请求和相关背景核对。

## 追问旧方向：显式查归档，而非重载全部历史

你说：“之前那条轻量分类分支为什么暂存了？”Agent 先按名称和用途用 lookup 加 include-archive 定位，获得状态、路径和引用，再把实际目标传给 main.review。它只展开该方向的决定与相关结果，核对当时的适用条件。

归档仅改变默认导航，旧记录、结果和冻结定义没有被搬走或覆盖。暂存不自动等于方法被否定，重新讨论也不自动恢复过去的执行范围。需要重开时形成当次真实选择，再更新主线与任务。

## 阶段交接：从可接续文档恢复

在一次实际阶段收束中，Agent 把下一阶段需要的核心问题、认识及条件、真实决定、设置版本、未解事项和首项工作写进 phase_summary。已结束的细节、临时推演和旧方向进入归档导航，原文件保持不变。用户的实际采纳覆盖了阶段文档时，publish 核对来源并封存，后续新认识进入新草案。

下一会话 main.open 优先得到当前阶段最近的已审阅 brief 与任务入口，阶段正文和原始证据按问题展开。来源发生变化或采用了新版设置时，包中标记需要复核，不将旧判断直接内联为当前事实。当前只是准备下一阶段文档而未选择转阶段时，项目 phase 保持原样。

## 包预算不足：保留完整来源入口

一份问题说明或阶段 brief 超出本轮预算时，packet 整体省略过大的字段，并留下来源位置及未加载原因。它不截取前半段后声称已掌握全文，必要的原文阅读按实际覆盖进行。多项内容确实都必要时拆成任务或提高明确预算，不能无声遗漏后继续下结论。

这些机制限制后续读取和包大小，正在进行的宿主聊天历史不会因此被脚本删除。新会话或宿主压缩后可以从阶段文档和当前任务恢复，不需要重放全部对话。实际宿主接入使用 [一句话引导](../shared/templates/router-bootstrap.md)，本案例没有修改全局提示词、创建新聊天或推进真实研究阶段。
