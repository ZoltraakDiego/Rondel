# 前期流程的交互验收示例

这是一组虚构场景，用于检查前期顺序、资源与笔记交互。实际流程见 [preparation](../../skills/rondel-main/references/preparation.md)，可读笔记样例见 [Obsidian 格式示例](../obsidian-notes/README.md)。示例没有连接真实机器、安装环境、下载数据或运行研究模型。

需要逐项查看从调取、Init 到 Main、前期、资源与笔记恢复的完整交互，阅读 [全场景使用案例](../usage-cases.md)。下文保留前期流程的简短验收情境。

## 核心论文未读就要求选基线

用户给出一个方向，直接要求“找个容易跑的基线”。Agent 先利用已有材料建立检索锚点，给出覆盖主要路线的候选和阅读依据，再定位核心原文与实际实现。研究者形成自己的摘要和疑问后，结合数据评价协议提出基线推荐；仓库易运行只作为可行性条件之一。

## 数据与环境不在同一台机器

用户说明 Agent 在本机、数据在实验服务器、GPU 由集群调度。资源层分别登记 host_id、连接或队列入口、数据、代码、环境与产物位置，核对是否有真实共享访问关系。陈旧或未知的空闲信息触发执行前复核，不将远程路径解析成本地路径，也不自动切回本机训练。

## 官方依赖与目标机器不同

选定基线后，Agent 检查来源版本、依赖与配置，再比较目标环境。实际建立环境沿已有授权范围推进，必要的核心适配说明差异和验证依据。导入、设备可见、样本可读与模型级检查分别保留完成范围，正式训练进入实验方案。

## 研究者在 Obsidian 中改了实验想法

视图使用平铺属性、关联双链和研究者批注区，主档案仍留在 `.rondal/`。Agent 通过只读状态检查定位编辑，回收为待审阅反馈；导出时发现编辑会保留原内容。冻结方案保持原样，Main 根据研究者实际选择创建修订或新方案，再更新当前计划。

## 一个实验结束后继续写论文

实际运行关联机器、数据、协议和产物，核验后在独立分析记录中说明结果、收益损伤与替代解释。论文工作稿引用这份证据，研究者先表达发现与边界，Agent 协助组织论证。缺少结果时保留待验证内容，模板中的空缺不会自动变成科学主张。
