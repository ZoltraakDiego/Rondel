# Pre 退出交互案例

以下场景展示当前退出流程的预期交互，相关论文、复现与资源状态均为虚构设定。实际项目需要读取对应原文、用户摘要、冻结设置和有效产物，再形成评审判断。完整条件见 [退出流程](../skills/rondel-main/references/pre-exit.md)，记录使用 [评审模板](../shared/templates/pre-exit-review.md)。

## 条件充分：推荐进入中期，并直接接续已选择的第一步

假设已完成约定的核心阅读和复现，用户能解释方法与关键对照，问题与冻结设置都有对应依据。Rondel 回应：“目前我对这个方向的理解是，我们关心少量示范条件下，哪些信息能够支撑可靠的时序分割。前期已经把主要路线、用户自己的摘要和实际复现对应起来，当前最值得追问的缺口也有明确来源。现有起点足以开始一轮有限验证，我建议结束本轮前期扩张，把其余外围论文保留为后续阅读。第一步先审阅轻量适配的最小对照，明确固定条件、预期行为和削弱解释的结果。”

它接着用一个短段落安排分工：“你先说明最希望改变的错误行为，以及什么观察会让你放弃这次解释；我整理匹配对照、设置引用与实际运行需求。产物是一份可共同审阅的有限方案，方案讨论结束就是下一次检查点。你希望按这一问题进入中期，还是先调整问题或范围？”用户回答：“进入中期，先看这份方案，不启动训练。”

Main 保存退出评审和真实决定，将 phase 更新为 investigate，next_step 指向方案审阅，原来的外围阅读仍是待办。它直接开始已经选定的方案整理，不再逐项请求同一选择。实际执行范围仍是讨论与整理，后续运行按具体方案接续。

## 条件不足：只补一个会改变判断的缺口

假设新旧复现混用了两种评价口径，用户问：“现在可以做自己的方法了吗？”Rondel 回应：“问题和核心阅读已经比较清楚，当前退出还缺的是一个可信的可比起点。两份结果使用的评价口径不同，我们还无法据此判断后续改动相对哪一个条件改善。下一项只核对评价实现与实际配置，并按需要补一份匹配结果；完成后再审阅这一处，不重新开始整轮论文阅读。”

有界补齐记录评价差异、对应设置和受影响比较，说明预期产物、用户与 AI 分工、投入窗口和检查点。项目仍在 prepare，原结果保留自己的版本与适用范围。若相同缺口再次出现，下一次复盘就要调整核对方式、实现对象或研究范围，不能只是再写一次“继续完善协议”。

## 有外围任务和资源等待：可以带入中期

假设已有可信复现和已核验的环境定义，首轮实验机当前繁忙，另有两篇外围论文未读。Rondel 回应：“这些剩余项目前不改变首轮对照的判断条件，我们可以把它们带入中期。今天先审阅方案与已有预测，外围阅读在相关问题出现时接回，真实运行等机器核对可用后再开始。你的可用时间有限，首轮先保留一个假设和一个核心对照。”

用户采纳后，Main 保留资源任务的 blocked 状态、外围阅读的 todo、各自负责人和复盘点，再更新当前计划。它不会为了显示前期完成而把未读论文标成 done，也不会把等待任务标为不适用。如果环境本身从未建立，导致首条可信复现仍然不存在，就改按上一类准备缺口处理。

## 用户还想继续读：将新增阅读与具体判断关联

用户说：“我还是想再读一些，怕漏掉关键工作。”Rondel 回应：“我们可以补最可能改变当前取舍的一条路线，先说明它与当前问题和核心集合的关系。如果新材料会改变协议、复现对象或局限判断，就安排有界补读并约定下一次收拢。其余材料保留在外围集合，现有条件已经充分时，先推进一个小验证也能带着更具体的问题回到阅读。”

这轮保留用户真实顾虑与实际选择，新增任务说明产物和检查点。它不把缺少信心解释成没有能力，也不让待读列表无限增加。若用户选定了具体补读对象，Main 准备相应原文并接续，不重复劝说同一选择。

## 用户选择提前转阶段，或明确暂停

用户说：“基线完整复现还没做完，但我想先进入中期讨论设计。”Rondel 回应：“可以先进入中期的设计讨论，评审里会保留基线证据尚未补齐这一条件。第一项任务限定为假设与对照审阅，当前结果还不能支持新方法相对基线的比较结论。我们把复现补齐作为正式执行与解释前需要完成的任务，原状态继续保留。”

Main 按真实选择记录提前转阶段的理由、未解决条件和有限首项任务，再更新 phase 与 next_step。若用户改为“这周先暂停”，则保留 prepare 并按明确指令记录 paused 与交接；已有进程分别按实际要求处理。退出评审结束于清楚的决定与接续位置，不自动创建研究运行或后台提醒。
